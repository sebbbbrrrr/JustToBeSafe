# JustToBeSafe — Autonomous Offline Content Worker Contract

**Scope:** Five scheduled editorial-content workers, each with an exclusive topic domain. These create drafts for the offline knowledge library, not approved public emergency guidance.

## Mandatory EVERY-RUN quality gate
1. Read root `AGENTS.md`, `PRODUCT.md`, `DESIGN.md`, `docs/OFFLINE_SEARCH_BULK_ROADMAP.md`, `docs/OFFLINE_KNOWLEDGE_LIBRARY.md` and the local skill orchestrator `.agents/skills/justtobesafe-design-workflow/SKILL.md`.
2. Before authoring or publishing a batch, **read the pinned locally downloaded skills**, relevant to the planned content:
   - `.agents/skills/impeccable/SKILL.md` and its relevant `audit`, `critique`, `harden`, `polish` workflow references, if present, for readability, structured scanning, accessibility, consistent information hierarchy, and visual representation.
   - Emil Kowalski's installed design-engineering skills in `.agents/skills/`, especially `emil-design-eng`, `break-ui`, `review-animations`, when guide cards or illustrations need visual/interaction work.
   - Do not claim a skill was used unless its actual instruction file was read this run. Use the skill only for what it is designed for; these **design skills cannot substitute for medical, electrical, fire, public-health or other subject-matter checks**.
3. Check open branches/PRs and all `content/batches/*.json`, plus existing baseline and urban articles, for overlapping titles, IDs and concepts **before** creating a new batch. Avoid simultaneous edits to the same files. Never commit to `main` or another worker's feature branch.
4. Each hourly run targets **6–15 substantively useful ORIGINAL articles** (minimum four only when credible and nonduplicative), with larger 25–50 batches allowed only when quality and context support it. Across five hourly workers, this is a *40–75 drafts/hour target*, not a guaranteed measured production rate. Fewer is better than redundant, shallow or invented material. Each article uses the schema from `scripts/import_knowledge_batches.py`: stable ID, title, category, summary, searchable tags/aliases, risk, illustration reference or null, review=`pending`, and at least 2 substantial sections with accurate and readable paragraphs. File location: `content/batches/<domain>-YYYYMMDD-<unique-run-id>.json`. Never overwrite an earlier batch.
5. Safety: keep medical, electrical/mains, structural, chemical, fire and other hazardous procedures at an informational, non-actionable overview/triage level unless independently professionally reviewed. All new content remains `internal_draft` and `review=pending`. Do not imply first-aid or repair procedures are approved. When source research is necessary for correctness, check dependable sources; do not invent exact thresholds, legal claims, rescue procedures or current alerts. Respect licensing; do not copy long passages or third-party artwork.
6. Illustration decision: assess each article for whether a visual materially helps identification, spatial understanding, comparisons, orientation or safe nonhazardous workflows. For a helpful schematic, include an actual in-app renderable `visual` object in its JSON article (not a placeholder note):
   `{"kind":"sequence|checklist|shelves|route","labels":["Short 1","Short 2","Short 3"],"alt":"A detailed accessible explanation of the visual","caption":"Brief explanatory caption"}`.
   The Android reader renders these from the existing native diagram templates at effectively zero per-image binary cost; the compiler validates labels, descriptions, and captions. For articles that need no visual, omit `visual` and record the decision in the batch report. Preserve legacy `illustration` references for existing images. Never use a generic flow diagram where it would mislead. Medical, electrical, chemical and public-health actionable illustrations **must not** be inserted as unreviewed generated diagrams; file an illustration-review task instead. Do not claim an illustration is embedded unless its `visual` object passes the importer and the native reader supports the kind. Review for 320dp / large text, accessible content descriptions, offline operation, and no external image URLs.
7. **Fast, mandatory per-batch validation:** run `python3 scripts/import_knowledge_batches.py`, `python3 scripts/check_content_quality.py`, `python3 scripts/build_knowledge_packs.py`, `python3 scripts/check_knowledge_packs.py`, `python3 scripts/build_fulltext_index.py`, `python3 scripts/check_fulltext_index.py` when available. Inspect new visual specifications and report if any are unrendered. Only run Android APK build and UI/device tests if actual UI, schema or art renderer changes; text-only hourly batches should avoid triggering repeated full Android SDK downloads/Gradle builds. A periodic integrated APK build can be scheduled separately when approved. Record what passed and what was not run. If shell tools are unavailable, do source-level validation where possible and report exact limitations.
8. **Skills QA checklist attached to each batch report/PR**: actual skill paths opened; content hierarchy/scanability; terminology/labels; accessibility; image alt/captions; mobile layout impact; reduced-motion relevance (usually none); duplication/scope; safety and rights; offline and compression integrity. Do not claim the skills proved technical accuracy.
9. **Reuse exactly one persistent standing branch and draft PR per worker domain**, based on `feature/offline-illustration-pipeline-throughput` or its approved successor: `worker/w1-first-aid`, `worker/w2-home-skills`, `worker/w3-food-water`, `worker/w4-urban`, `worker/w5-outdoors`. Create a standing branch/PR if absent, otherwise append a **new uniquely named batch file** to the existing branch; do not overwrite past files or open an additional PR each hour. If the base updates, inspect the diff and reconcile without force-push. Never automatically merge, deploy or publish. No unnecessary GitHub Actions builds. If cannot write to GitHub, report the blocker rather than claiming a commit.
10. End each run with actual count of unique articles committed, cumulative count on standing PR, how many meaningful native diagrams rendered and which were deferred for expert review, branch/PR or blockers, files changed, downloaded skills inspected, static/test results, duplicate scan, measured compressed bytes if available, and unfilled topics. Never manufacture counts, diagrams, speed or test evidence.

## Exclusive editorial domains
- **W1 first aid:** basic first-aid concepts, household health and hygiene; qualified clinical review required for any treatment procedures.
- **W2 home utilities:** nonhazardous home maintenance, equipment recognition, property and plumbing; mains electricity, gas, structural repairs need competent oversight.
- **W3 food & water:** shelf-stable food, storage, hygiene, sanitation, water provider notices; food-safety and public-health review for treatment advice.
- **W4 urban disruption:** common outages, weather, communication, transport, floods, household plans, emergency contacts; national and local distinctions.
- **W5 outdoors:** navigation, exposure awareness, equipment and practical outdoor preparation; hazardous survival methods need appropriate review.

## Conflict policy
- Use one **persistent unique branch per domain** and a new unique content batch file per hourly run; never create multiple hourly PRs for the same domain.
- Re-fetch base and detect duplicates immediately before commit.
- Never force-push, modify another worker's branch or merge an unreviewed batch.
- If a prior run is still unresolved, avoid concurrent writes to the same standing branch; detect duplicates and await/reconcile before adding another batch.
- An automation is a **scheduled assistant execution**, not a guaranteed always-running server process. GitHub writes/builds and skill access depend on tool connectivity in that run.
